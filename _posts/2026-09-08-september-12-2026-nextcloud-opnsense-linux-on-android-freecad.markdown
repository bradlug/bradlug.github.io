<p><strong>Darren:</strong> asked about setting up <a href="https://nextcloud.com/" type="text/html" role="link">Nextcloud</a> in order to give a demonstration for a U3A group; David said that he would need a proxy webserver, a proper domain name and an IP number to get Nextcloud to work or <a href="https://nextcloud.com/sign-up/" type="text/html" role="link">Nextcloud hosting</a>. David went on to warn that, when it becomes permanent, Nextcloud makes lots of demands, specifically in relation to the version of PHP. For example, if using <a href="https://slackbuilds.org/" type="text/html" role="link">Slackbuilds</a>, he would recommend Slackware Stable; he would then need to keep Nextcloud and PHP up-to-date. He could also use the Docker instance in Slackware Stable but, whichever he used, he would also need to ensure router security. VPS is an alternative but Nextcloud hosting is cheaper.</p><p>Steve commented that he did not use Docker but Linux containers on <a href="https://www.proxmox.com/en/proxmox-virtual-environment/overview" type="text/html" role="link">Proxmox server</a>.</p><p><strong>John:</strong> then gave the <a href="http://www.bradlug.co.uk/blog/2026/09/08/files/Eighteenth_Birthday.pdf" type="application/pdf" role="link">Birthday presentation</a>.</p><p>David commented in relation to the mention of microfortnights that, even though the documentation said microfortnights, they were actually implemented as seconds.</p><p><strong>Brian:</strong> said that he wasn’t able to get H.265 to run; David commented that a lot of distributions had not included H.265 in <code>ffmeg</code> because of fears about patent trolls. However, most now included the relevant codecs. John noted that <a href="https://gnucash.org/" type="text/html" role="link">Videolan</a> is offering the x265 software library.</p><p>Unfortunately, someone had put in a pull request in <a href="https://www.home-assistant.io/" type="text/html" role="link">Home Assistant</a> to revert to H.264 on which nobody had commented!</a><p><strong>Steve:</strong> reported on his move from <a href="https://www.pfsense.org/" type="text/html" role="link">pfSense</a> to <a href="https://opnsense.org/" type="text/html" role="link">OPNsense</a>; he had asked ChatGP to give some simple answers and it had generated a Python script to recover all the static data. The <code>config</code> files are different in pfSense and OPNsense but he had been able to use the static data.</p><p>On Saturday he had switched over and everything went fine except that Windows couldn’t see the Samba shares because it needs to have an active directory server to see them. So Steve had captured the <a href="https://en.wikipedia.org/wiki/Dynamic_Host_Configuration_Protocol" type="text/html" role="link">DHCP</a> conversations using <a href="https://www.wireshark.org/" type="text/html" role="link">Wireshark</a>.</p><p> DHCP has a vendor class identifier for Windows and, as in OPNsense you can set conditional options, he could use the vendor class identifier to set the DNS server to point to the active directory server for Windows machines though, once you configure an active directory server with a domain, you cannot change it. However that was better than pfSense where he had to use the active directory server for everything.</p><p>Brian commented that he had used Mac addresses for identification though, in this case, you cannot tell if an IP address is running.</p><p>So Steve shared how you could pass DHCP options; a conversation starts with a broadcast message to which the device responds with a broadcast message after which DHCP makes an offer and the device accepts it.</p><p><strong>Brian:</strong> has his laptop connected to his TV via HDMI but could not initially get the sound on the TV; so, after some experimenting, he developed a script which would turn on the sound on the TV and turn it off. He then added a <code>systemd</code> service to do it automatically.</p><p>Picking up his question in March about Linux on Android, he had identified: <a href="https://grapheneos.org/" type="text/html" role="link">GrapheneOS</a> only been available on Pixels, <a href="https://www.ubuntu-touch.io/" type="text/html" role="link">Ubuntu Touch</a> available for the Pixel 3A but development by Canonical was terminated in 2017 though community development continued for some time afterwards; <a href="https://postmarketos.org/" type="text/html" role="link">PostmarketOS</a>; <a href="https://sailfishos.org/" type="text/html" role="link">Sailfish</a>. John commented that he thought Sailfish had died [but later found that it has been <a href="https://forum.sailfishos.org/t/jolla-phone-update-deliveries-started-and-other-next-steps/30730" type="text/html" role="link">revived</a>].</p><p>Steve noted that <a href="https://motorolanews.com/motorola-three-new-b2b-solutions-at-mwc-2026/" type="text/html" role="link">Motorola</a> are bringing out smartphones with GrapheneOS in 2027.</p><p>Brian mentioned that the Chinese have developed sodium batteries for storage which prompted John to recall a couple of the afternoon presentations at the <a href="https://oshug.org/event/oshcamp2026" type="text/html" role="link">Open Source Hardware Camp</a>.</p><p><strong>John:</strong> said that Martin Lomas had described how he uses his electric car battery to power his home. The electricity he uses to charge the car overnight costs a third of the price. You use camping mode and need a bi-directional charger cable; you also need to be aware of the regulations and make sure the earthing is correct.
